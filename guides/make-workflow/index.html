Automate the handoff.
Keep the judgment.

A request arrives. Someone copies it into a sheet, checks the same fields and nudges the next person. That handoff is a better starting point than trying to automate your entire business.

This is an evergreen planning guide, not breaking news or a report of a workflow we personally tested.

Pick one task with a clear finish line

Start with a repeatable administrative task: a new approved row becomes an internal task or draft. Make connects apps through scenarios. You still need to check whether the exact modules, account permissions and plan limits fit your workflow.

  • Good first experiment: an approved request in a spreadsheet becomes a draft for review. Success means the right draft exists once, with the original request ID.
  • Another option: log messages from a designated inbox label into a sheet, using the message ID to detect repeats.
  • Keep manual: refunds, bank transfers, legal commitments, sensitive decisions and ambiguous customer complaints. A wrong action here costs more than saved copying time.

A small, testable Sheets → draft workflow

  1. Define the queue. Use a dedicated sheet with Request ID, Status, Recipient and Draft ID. Limit access and avoid unnecessary sensitive data.
  2. Choose the trigger. Make’s Google Sheets “Watch New Rows” module is for new rows. Blank rows can stop it processing later rows. Changing an old row to Approved is a different trigger requirement; check the module rather than assuming an edit will start the workflow.
  3. Filter before action. Continue only when required fields exist and the request meets your approval rule. A filter controls which bundles move to the next module.
  4. Check for a prior result. Use Request ID and the saved Draft ID to detect a replay. This is a design requirement, not a guarantee of exactly-once delivery.
  5. Create a draft, not an automatic send. Map only the necessary fields, inspect the draft and keep final review with a person. Write the returned ID into the queue.
  6. Reconcile uncertainty. If an error occurs after the draft might have been created, look for that draft before rerunning. Check Make’s error-handling settings; incomplete executions are disabled by default.

Before connecting real customer data, test with non-sensitive sample records in your own test sheet. Check missing fields, duplicate IDs, blank rows, revoked permissions and an uncertain action result. Check the current plan’s credits and scheduling limits; stop at your budget rather than enabling an automatic upgrade.
